# DC Assistant

نسخة أولى لمساعد Document Control على Windows، بإعدادات مستقلة لكل مشروع.

## الموجود في النسخة 0.1

- شاشة بداية: مشروع مسجل أو مشروع جديد.
- حفظ المشاريع واللوج والدفعات السابقة في قاعدة بيانات محلية، واسترجاعها بعد إعادة التشغيل.
- تعريف أجزاء اسم اللوحة من مثال صحيح. كود المشروع يُحفظ كنص، بما فيه الأصفار. أي بدائل للكود يجب إضافتها صراحةً في إعدادات المشروع.
- استيراد Excel بعد تحديد الشيت وصف العناوين والأعمدة. لا يُحسب عدد السجلات من صفوف القالب المرقمة الفارغة.
- حصر PDF وDWG، والمطابقة مع السجل بحسب رقم المستند والإصدار.
- حصر ملفات إضافية مثل Excel وBBS والموديلات والصور في قائمة مستقلة، دون اعتبارها لوحات أو فحص محتواها هندسيًا.
- قراءة رقم المستند والإصدار من نص أول صفحة PDF ومقارنتهما باسم الملف.
- قارئ بديل للـPDF المعقد عند تعذر القراءة السريعة، ويمكن تعطيله من إعدادات المشروع لتقليل وقت الفحص.
- إظهار الأسماء غير المطابقة، وتعارض الإصدارات، وتكرار سجلات اللوج، والملفات المتطابقة أو المختلفة لنفس الرقم والإصدار والصيغة.
- تصدير تقرير XLSX جديد. ملفات المصدر لا تتغير.

## بداية الاستخدام

1. افتح البرنامج واختر «مشروع جديد»، ثم اكتب الاسم والكود.
2. في «قواعد التسمية»، اكتب اسم ملف صحيح واضغط «عرض أجزاء المثال». حدد الأجزاء الثابتة، وكود المشروع، والتخصص، والمنطقة، والرقم التسلسلي، والإصدار. يجب تحديد جزء الرقم التسلسلي.
3. أضف بدائل أكواد المشروع أو أسماء الفولدرات المستبعدة فقط إذا كانت معتمدة عندك؛ لا يُستبعد OLD تلقائيًا.
4. استورد اللوج وحدد صف العناوين وأول صف بيانات كلًا على حدة، ثم الأعمدة. اختيار عمود الحالة اختياري، ويجب أن يخص عمود الإصدار المحدد. البرنامج لا يستنتج معنى أعمدة Rev-00/01/02 تلقائيًا.
5. اختر فولدر دفعة محددة للفحص، ثم افتح النتائج أو صدّر Excel.
6. عند الاستخدام التالي اختر «مشروع مسجل». إعدادات كل مشروع ولوجه ودفعاته منفصلة عن الآخرين.

يُحفظ البرنامج افتراضيًا بياناته في `%LOCALAPPDATA%\DCAssistant\dc-assistant.sqlite3`. يمكن تحديد مكان مختلف عند التشغيل باستخدام `--data-dir`.

## حدود هذه النسخة

فحص DWG يقتصر على الاسم والحصر؛ لا يقرأ Layouts أو محتوى الرسم. ملف DWG قد يحتوي أكثر من لوحة، لذلك لا يُفترض أن يقابل كل PDF ملف CAD منفرد.

قراءة PDF نصية لأول صفحة. الملفات المصورة والحقول التي لا تُقرأ تُعلّم للمراجعة أو OCR. لا يوجد حاليًا استخراج عام لعنوان اللوحة من الـTitle Block، أو فحص اللوجو والإطار، أو تحليل ردود JPG وواتساب والإيميل. العناوين والحالات المعروضة تأتي من اللوج المستورد عند وجود ربط واضح.

«غير موجود في الدفعة» يعني عدم وجود PDF مطابق لرقم السجل وإصداره في الفولدر المختار، ولا يعني أنه ناقص من المشروع. لا يُعتبر اختلاف إجمالي تقريرين خطأ دون تعريف نطاق كل تقرير.

التصدير حاليًا تقرير مطابقة مستقل. الحفاظ على قوالب Excel الأصلية، وتجميعات التقارير المخصصة، وتجهيز Transmittals، واستقبال الردود من المصادر المختلفة تأتي في مراحل تالية. ملاحظات إجراءات المشروع تُحفظ كمرجع في هذه النسخة.

## تشغيل الكود

يتطلب Python 3.12 على Windows، مع Tkinter.

```powershell
python -m pip install -r requirements.txt
python launcher.py
```

## استخراج EXE

```powershell
python -m pip install -r requirements-build.txt
./build-windows.ps1
```

النتيجة المتوقعة: `dist/DC-Assistant/DC-Assistant.exe`. احتفظ به داخل فولدره ومعه `_internal`. عند توزيع النسخة، اضغط فولدر DC-Assistant كاملًا؛ لا تنقل EXE وحده.

يوجد إعداد GitHub Actions يشغّل الاختبارات ثم يبني البرنامج ويختبر ملفه التنفيذي على Windows عند رفع الكود إلى main/master أو تشغيل Workflow يدويًا. تظهر الحزمة في Artifacts باسم DC-Assistant-Windows. فك الحزمة ثم افتح EXE بجانب فولدر `_internal`. إعداد البناء يعتمد على [PyInstaller](https://pyinstaller.org/en/stable/) و[GitHub Actions](https://docs.github.com/en/actions/concepts/workflows-and-actions/workflow-artifacts).

## الاختبارات

```powershell
python -m unittest discover -s tests -v
```

الاختبارات تستخدم بيانات مصطنعة داخل `.test-tmp`؛ لا تحتاج ملفات مشروع حقيقية.
