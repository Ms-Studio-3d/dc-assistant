# DC Assistant 0.1.1

إصدار إصلاحات للحصر ومطابقة المستندات على Windows. إعدادات كل مشروع ولوجه ودفعاته مستقلة.

## ما الذي أُصلح؟

- ملف Excel التالف لا يترك نافذة فارغة حاجزة للتفاعل.
- قراءة الصفوف والأعمدة لا تعتمد على أبعاد الشيت المعلنة وحدها.
- المعادلات التي لا تملك نتائج محفوظة وأخطاء Excel والصفوف ذات البيانات دون رقم تظهر بموقعها. الواجهة ترفض استيراد النتيجة الناقصة وتحافظ على اللوج المحفوظ سابقًا.
- صفوف القالب الفارغة، حتى التي تحتوي معادلات مساعدة، لا تعتبر مستندات. نتيجة المعادلة المخزنة كنص فارغ تختلف عن عدم وجود نتيجة محفوظة.
- الرقم الرقمي الصحيح لا يتحول إلى `1.0`. تنسيق أصفار Excel الصريح مثل `00000` يحترم، والنصوص الأصلية لا تزال نصوصًا. لا يوجد تخمين لعدد الأصفار.
- أكواد الحالات ومعانيها تستخدم تعريف المشروع نفسه؛ الكود غير المعرّف يظهر للمراجعة. لا تنقل الحالة دون ربط واضح بإصدار محدد.
- اختلاف أكواد التخصص أو المنطقة بين الاسم واللوج يظهر بالقيمتين. هذه مقارنة نصوص؛ لا يفترض البرنامج تطابق اسم مبنى وصفي مع كود رقمي دون تعريف.
- تعارض إصدار داخل رقم السجل مع عمود إصداره يمنع الربط ويظهر سببه في التقرير.
- بدائل كود المشروع لا تفسد فهرسة أجزاء الاسم. التعريفات المتداخلة الملتبسة ترفض قبل استخدامها. تدعم الأجزاء المتغيرة الحروف العربية و`_` و`+` عندما لا تكون فاصل الأجزاء.
- وجود الرقم في نص PDF لا يقدم كتحقق من خانة اللوحة. وجود أرقام أخرى أو صفحات بعد الأولى يظهر للمراجعة. نتائج الدفعات القديمة تعرض مع بيان حدود فحصها.
- قراءة نص CAD السريعة تستخدم PDFium، مع قارئي pypdf وpdfminer بديلين. لا يضاف استخراج حقول LOD إلى هذه النسخة.
- قارئ PDF يعمل في عملية منفصلة بمهلة 30 ثانية للملف، وتنهى العملية عند تجاوزها. زر الإلغاء يوقف العمل دون حفظ دفعة جزئية. يمكن ضبط `pdf_timeout_seconds` في إعدادات المشروع برمجيًا حتى 300 ثانية.
- يحسب hash للمجموعات المرشحة للتكرار فقط. النسخة المتطابقة ملاحظة معلوماتية، والتعارض له درجة خطورة منفصلة.
- قاعدة البيانات لها إصدار مخطط واضح، وإدخالات بأسماء أعمدة. ترقية بيانات 0.1 تحفظ السجلات والدفعات. قاعدة أحدث من البرنامج ترفض بدل تخفيض إصدارها.
- تصدير Excel يكتب ملفًا مؤقتًا ثم يستبدل التقرير بعد اكتمال الكتابة؛ فشل الحفظ لا يستبدل التقرير السابق بملف جزئي. ملفات المصدر محمية من الاستبدال.

## بدء الاستخدام

1. فك حزمة Windows كاملة وشغّل `DC-Assistant.exe` بجانب مجلد `_internal`.
2. اختر مشروعًا مسجلًا أو أضف مشروعًا جديدًا.
3. عرّف اسم المشروع وكوده ومثال التسمية ووظيفة كل جزء. الكود يحفظ بأصفاره، والبدائل تحتاج تعريفًا صريحًا. إذا لم يتضمن اسم الملف إصدارًا، فلا تعرّف جزءًا آخر مثل `RR00` بوصفه إصدارًا دون سند من نظام المشروع.
4. عرّف أكواد الحالات ومعانيها حسب المشروع؛ لا يستنتج البرنامج أن U وUR متطابقان.
5. استورد اللوج، وحدد الشيت وصف العناوين وأول صف بيانات والأعمدة. اختر أعمدة أكواد التخصص والمنطقة التي يمكن مقارنتها بأجزاء الاسم. عند وجود تحذيرات استيراد أصلح الصفوف المذكورة؛ اللوج السابق يظل محفوظًا.
6. اختر فولدر الدفعة وافحصه. البحث النصي في PDF اختياري. افتح تفاصيل الملف لقراءة نتيجة البحث ثم صدّر تقرير Excel مستقلًا.

حفظ البيانات افتراضيًا في `%LOCALAPPDATA%\DCAssistant\dc-assistant.sqlite3`. اختيار مسار مختلف ممكن باستخدام `--data-dir`.

## حدود الفحص

فحص PDF في هذا الإصدار بحث نصي في **أول صفحة**. حتى عند العثور على الرقم والإصدار، خانة اللوحة تظل غير متحققة؛ النص قد يكون مرجعًا لمستند آخر. الصفحات التالية لا تفحص. عند فشل القراءة يظهر السبب، وقد تحتاج قراءة يدوية أو OCR. لا يوجد استخراج عام لإصدار اللوحة أو عنوانها من الـTitle Block في هذا الإصدار.

العناوين والحالات المرتبطة المعروضة تأتي من اللوج. فحص DWG يقتصر على الاسم والحصر، ولا يقرأ Layouts أو محتوى CAD. لا توجد مراجعة هندسية، أو فحوص لوجو وإطار، أو استقبال تلقائي لردود الإيميل والصور وواتساب.

«غير موجود في الدفعة» يعني غياب PDF مطابق داخل الفولدر المختار، ولا يعني أنه ناقص من المشروع. اختلاف إجمالي تقريرين يتطلب فهم نطاقهما.

الاستيراد يحدد أعمدة إصدار واحد وحالته؛ قراءة جميع مجموعات أعمدة Rev-00/01/02 تلقائيًا لم تنفذ. استخراج LOD الجديد غير المكتمل خارج هذا الإصدار.

## تنظيم الكود

| الملف | المسؤولية |
| --- | --- |
| `app.py` | الواجهة الرئيسية وتشغيل الفحص وعرض النتائج |
| `dialogs.py` | إعدادات المشروع واستيراد اللوج |
| `naming.py` | تفسير أجزاء الاسم وفق إعدادات المشروع |
| `registers.py` | قراءة Excel وتشخيص الصفوف والمعادلات |
| `scanning.py` | الحصر والربط ومقارنة الحقول والتكرار |
| `pdf_checks.py` | قراءة PDF بمهلة وإلغاء وحدود نتيجة البحث |
| `issues.py` | أكواد الملاحظات وخطورتها وعرض الحالة |
| `storage.py` | قاعدة البيانات وإصدار مخططها |
| `reports.py` | تصدير Excel مستقل وكتابة القيم كنصوص آمنة |
| `diagnostics.py` | فحوص النسخة التنفيذية بملفات مصطنعة ونص PDF فعلي |
| `core.py` | واجهة استيراد متوافقة للكود السابق |

التنسيق بواسطة Black، مع فحص تنسيق إلزامي قبل بناء EXE.

## تشغيل المصدر والبناء

يتطلب Python 3.12 وTkinter على Windows.

```powershell
python -m pip install -r requirements.txt
python launcher.py
```

لبناء EXE:

```powershell
python -m pip install -r requirements-build.txt
./build-windows.ps1
```

الناتج `dist/DC-Assistant/DC-Assistant.exe` ومعه `_internal`. سكربت البناء يفحص التنسيق، ويشغّل الاختبارات، ويبني EXE مع موارد pdfminer، ثم يختبر EXE نفسه. إعداد GitHub Actions ينفذ السكربت نفسه ويضع الناتج في Artifacts. رفع المصدر إلى GitHub يتم بواسطة صاحب المستودع.

## التحقق

```powershell
python -m black --check --workers 1 dc_assistant tests launcher.py
python -m unittest discover -s tests -v
```

اختبارات الانحدار تشمل ملفات Excel ذات الأبعاد الخاطئة والمعادلات، والربط والحالات، ونافذة الاستيراد، وPDF يحتوي رقمًا مرجعيًا، وملفًا متعدد الصفحات، وإيقاف عملية قارئ معلقة. فحص EXE الذاتي يقرأ نصًا فعليًا بالقارئات الثلاثة ويتحقق من موارد CMap؛ نجاحه لا يحول البحث النصي إلى تحقق من الـTitle Block.

الاختبارات المرفوعة تستخدم بيانات مصطنعة فقط. لا تحتوي الحزمة ملفات مشروعات المستخدم.
